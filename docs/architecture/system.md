# SubAlign 系统架构

## 1. 系统定位

SubAlign 是一个本地运行的命令行工具，只做一件事：以视频音轨为时间基准，校正外挂字幕的时间轴。

它不生成字幕、不翻译、不修改字幕文本，也不替播放器做渲染。输入是「视频 + 已有字幕」，输出是「时间被修正的新字幕 + 一份可复核的对齐报告」。

## 2. 分层与模块边界

| 层 | 模块 | 职责 | 不负责 |
| --- | --- | --- | --- |
| 交互层 | CLI | 参数校验、编排、退出码、错误提示 | 媒体解析、对齐算法 |
| 媒体层 | Media | 探测时长与音轨、抽取 16kHz / 单声道 / PCM s16le WAV、临时文件生命周期 | 语音识别 |
| 字幕层 | Subtitle | 解析 SRT/ASS、保留样式与事件字段、语言标注、双语分组 | 音频分析 |
| 识别层 | ASR | 调用 whisper.cpp 产出 token 级时间戳与置信度 | 字幕文本比对 |
| 对齐层 | Align | 把字幕行或双语锚点文本与 token 流做相似度对齐，产出音频锚点 | 全局模型选择 |
| 拟合层 | Fit | 在常量、线性、分段常量之间选择偏移模型，产出每行修正量 | 写文件 |
| 输出层 | Writer / Report | 原子写回新字幕、生成 JSON 报告与告警 | 再次修改时间 |
| 评估层 | Eval | 人工基准对比、基线对比、注入断点实验 | 参与运行时决策 |

模块之间只通过数据契约通信：token 流、字幕文档、双语组、锚点、偏移模型、报告。任何模块都不直接读写其他模块的临时文件。

## 3. 运行数据流

```text
视频 ──ffmpeg──▶ 16kHz 单声道 PCM s16le WAV ──whisper.cpp──▶ token 级时间戳
                                            │
SRT/ASS ──解析/归一化/语言分组──▶ 字幕行与锚点行 ◀───┘
                        │
                  文本-token 流对齐
                        │
                  每行音频锚点
                        │
              常量 / 线性 / 分段拟合
                        │
              新 SRT/ASS + JSON 报告 + 原文件不动
```

异常路径统一走「停止写回」：媒体错误、字幕解析错误、覆盖率不足、模型歧义都只产出报告或错误信息，不产生新字幕文件。

## 4. 技术栈与约束

| 项 | 选择 | 约束 |
| --- | --- | --- |
| 语言 | Python 3.11 | 以 macOS arm64 为主要运行环境 |
| 媒体处理 | ffmpeg / ffprobe | 版本 ≥ 6.0；输出固定为 16kHz / 单声道 / PCM s16le WAV，识别层不接受其他格式 |
| 语音识别 | whisper.cpp（GGML 模型，DTW token 时间戳） | 首次运行需下载 GGML 模型；之后可离线 |
| 字幕读写 | SRT 与 ASS/SSA（v4+） | 保留原文、样式与事件字段，只改时间码 |
| 数值计算 | numpy / scipy | 偏移拟合与变点检测 |
| 运行位置 | 本机 | 不上传音视频，不依赖服务端 |

## 5. 设计原则

1. **音轨是唯一时间基准。** 字幕文本只用来定位「这句话在音轨的哪里」，不用来推断「应该延迟多少」。
2. **原始文件只读。** 任何运行都不覆盖输入字幕，输出必须落在新路径。
3. **宁可不改，不可改错。** 置信度不足或模型歧义时输出「无需修正」，而不是猜测一个偏移。
4. **每次运行可解释。** 每行修正量、置信度、选中的模型与断点都必须出现在报告里。
5. **格式不转换。** SRT 与 ASS 各自原样读写，ASS 只改 `Dialogue` 的 `Start`/`End`；不通过中间格式往返，避免样式与定位丢失。
6. **精度优先于吞吐。** 单机长片能跑完即可，本阶段不追求批量与服务化。

## 6. 演进边界

当前架构覆盖单文件、中英单语或双语、SRT 与 ASS 的本地校正。批量队列、ASS 卡拉OK逐字时间重算、GUI 与播放器集成、中英以外语言的同等精度，均不在当前架构的模块边界内；引入时需要新增交互层与输出层适配，不改动对齐与拟合两层的契约。
